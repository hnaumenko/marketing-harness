# Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create the domain-agnostic agent harness (guardrails, router, dev and manager modes) for this repository.

**Architecture:** Markdown-only layered harness. `CLAUDE.md` imports `AGENTS.md` (persona and guardrails); the `mdt` skill routes a mode and instructs explicit reads of `_shared.md` → `_profile.md` → `_custom.md` → the mode file. System layer holds no project facts; user layer holds all of them.

**Tech Stack:** Markdown, one YAML file, `grep`/`ls` for verification. No code, no scripts.

**Spec:** `docs/superpowers/specs/2026-11-20-harness-design.md`

## Global Constraints

- Harness files are in English; generated-output language comes from `config/project.yml` key `language.output`, default `ru`.
- System-layer files (`AGENTS.md`, `CLAUDE.md`, `DATA_CONTRACT.md`, `.claude/skills/mdt/SKILL.md`, `modes/_shared.md`, `modes/{rfc,adr,assumptions,review-ai-code,intake,stakeholder-msg,metrics}.md`, `modes/*.template.md`) contain **no domain terms**. Forbidden pattern (case-insensitive): `conversion|pixel|postback|click.?id|network [abc]|gclid|kafka|mariadb|chargeback|gtm|monolith|marketing`.
- Skill name is `mdt`; modes are exactly: `rfc`, `adr`, `assumptions`, `review-ai-code` (dev); `intake`, `stakeholder-msg`, `metrics` (manager).
- Provenance marker syntax, verbatim: `source: <file> | official-doc <URL, date> | user-stated YYYY-MM-DD | derived-unverified | user-cannot-confirm`.
- Four confirmation outcomes, verbatim: (a) accurate, (b) correct the value, (c) narrative-only, (d) "I don't know" → durably `user-cannot-confirm`. Never yes/no.
- No scoring, no tracker, no scripts, no plugin, no nested subagents.
- Nothing is committed unless the user says so. (At planning time the repo had no commits; the harness has since been committed in `bbb91d6`.)

## Review Focus

- A user-specific fact written into a system-layer file (breaks the update contract): covered by the domain-term grep in Task 6 and the Data Contract rule in Task 1.
- Router names a mode whose file does not exist, or a mode missing from the routing table: covered by the cross-check in Task 5.
- Untrusted content (pasted text, third-party docs, other teams' repos) containing instructions: each mode that takes external input must carry the "quote as anomaly and continue" line; checked in Tasks 3–4.
- A derived-layer fact (the two research files) cited without a marker: `assumptions` and `rfc` must refuse to restate it as settled; checked in Task 3.
- Irreversible action (send, publish, merge) performed without review: `stakeholder-msg` and `review-ai-code` must end with an explicit stop; checked in Tasks 3–4.

### Task 3: Developer modes

**Files:**
- Create: `modes/rfc.md`, `modes/adr.md`, `modes/assumptions.md`, `modes/review-ai-code.md`

**Interfaces:**
- Consumes: register row format and ADR naming from Task 2.
- Produces: each file starts with `# Mode: <name> — <purpose>` and an "Untrusted input" paragraph.

- [ ] **Step 1: `modes/rfc.md`.** Sections the mode must deliver: context, goals/non-goals/anti-goals, options with trade-offs, decision, risks, open questions, "Assumptions" section that lists register ids. Step 1 of the mode: check every cited fact has a primary source or a marker; unmarked derived facts are not restated as settled. Output language per `language.output`.
- [ ] **Step 2: `modes/adr.md`.** One decision per file: context, options, choice, consequences, status; written to `docs/decisions/NNNN-<slug>.md` with the next free number.
- [ ] **Step 3: `modes/assumptions.md`.** Add/update rows in `docs/assumptions.md`; any unconfirmed claim is surfaced with the four outcomes verbatim and never as yes/no; outcome (d) sets status `user-cannot-confirm` permanently (re-citation cannot change it).
- [ ] **Step 4: `modes/review-ai-code.md`.** Risk-tiers a change (low / medium / high) with stated criteria, says which tiers need manual review, gives a checklist for AI-generated code and for code in another team's repository (changes there become a maintainer proposal), and ends with an explicit STOP: never merge or approve on the user's behalf.
- [ ] **Step 5: Verify.** Run the forbidden-pattern grep on the four files; expected no output. Run `grep -L 'Untrusted input' modes/{rfc,adr,assumptions,review-ai-code}.md`; expected no output (every file has the paragraph).

### Task 4: Manager modes
